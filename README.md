# Procedural Dungeon Generator & Roguelike System

Unity上で動作する、BSP（二分空間分割）アルゴリズムを用いたダンジョン自動生成システムおよび2Dローグライク基盤。

## 1. システム概要
- **アルゴリズム**: BSP（二分空間分割）ツリーによる動的空間分断 
- **データ駆動設計**: Prefab/Tilemapを自動解析・キャッシュするプリセット部屋構造
- **デバッグ環境**: Gizmosを用いたツリー構造のリアルタイム可視化ツール

## 2. 主要機能と技術的特徴
### ■ BSPアルゴリズムによる部屋生成と制御

- **面積優先分割ループ**: 最も面積の大きい領域の分割をし、分割後の領域を分割前の領域に葉として保持させる木構造を採用
  
  元来は単純なリスト構造でデータを管理していたが、BSP本来の強みを活かせていないことを知り、木構造に変更した
  
- **アスペクト比保護**: `partingMargin` による分断位置のクランプ

  分割位置の乱数の範囲によってバグが生じていたため、改善と共に分割位置を調節できるようにした

### ■ BspVisualizer（開発支援ツール）
- BSPの結果がどのような状態になったかを確認するために制作したツール

### ■ シングルトンパターン（MonoBehaviour Singleton）によるアクセス最適化
- 全体から参照されるマネージャーに対し、インスタンス自身を静的に保持するシングルトン構造を適用。

はじめて使用した当時は、静的・動的の理解が浅かったが、学習をしていくうちにシングルトンパターンの価値を実感した。

### ■ データ駆動型設計（Data-Driven Architecture）
-  マップを構成するクラスのデータや、マップ生成で使用する部屋の形を保存し、そこから生成するために活用した
-  `TileMap`からゲームの実行に必要な情報を得るために、Tileと設定を対応付けて保存するために活用した。

## 3. 技術的反省（Lessons Learned）

### ■ 必要以上のファイル数の増加
開発途中にデータ駆動型などの手法を知り、なんとか自分のプロジェクトに取り入れようと工夫した結果、ファイル数が増加してしまった。

### ■ 基本情報技術者試験の学習と事前設計の重要性の実感
初期にデータ駆動型を使用すると想定せずに開発を進めたため、新しい技法を途中から導入することに苦労した。その難しさから基本情報技術者で学んだUMLの必要性を実感した。


## 4. 今後の展望（Future Work）

### ■ 静的地形データ（TerrainMap）に基づく経路探索（A*）の事前計算
本システムで分離・生成した `TerrainMap` の静的なグリッド構造を活用し、敵ユニットなどの動的オブジェクトが利用する A* 経路探索のノード情報を事前に計算する処理を想定しています。

### ■ キャッシュ機構と両立する部屋データの動的変換（回転・反転）
`RoomDatabase` の遅延キャッシュ構造を拡張し、1つの `RoomData` プレハブから90度・180度回転および左右反転したデータを自動生成・保持するパイプラインを構築します。

### ■ 大学での学術的探求とシステムの再構築
今回の開発で得た「設計とアルゴリズム」の反省と気づきをベースに、大学進学後は情報工学・ソフトウェア工学を体系的に学びます。実装前にUMLによる厳密なアーキテクチャ設計を行い、今回の知見を活かしたより柔軟で拡張性の高いプロシージャル生成基盤の再構築に挑戦します。
