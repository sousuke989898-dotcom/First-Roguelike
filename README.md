# Procedural Dungeon Generator & Roguelike System

Unity上で動作する、BSP（二分空間分割）アルゴリズムを用いたダンジョン自動生成システムおよび2Dローグライク基盤。


## 開発・動作環境

- **Engine**: Unity 6.3 LTS (6000.3.11f1)
- **Language**: C#
- **Template**: Universal 2D

## 1. システム概要

- **アルゴリズム**: BSP（二分空間分割）ツリーによる動的空間分断 
- **データ駆動設計**: `Prefab` / `Tilemap` を自動解析・キャッシュするプリセット部屋構造
- **デバッグ環境**: `Gizmos` を用いたツリー構造のリアルタイム可視化ツール（`BspVisualizer`）

## 2. 主要機能と技術的特徴
### ■ BSPアルゴリズムによる部屋生成と制御

- **面積優先分割ループ**
  最も面積の大きい領域を優先して分割し、分割後の領域を分割前の領域の葉として保持させる木構造を採用。
  * **背景**: 元来は単純なリスト構造でデータを管理していたが、BSP本来の階層構造や空間の包含関係を活かせていないことを知り、木構造へリファクタリングを行った。

- **アスペクト比保護と境界制御**
  `partingMargin` による分断位置のクランプ処理を実装。
  * **背景**: 分割位置の乱数計算範囲によって極端に細長い空間が生成されるバグが発生していたため、境界値の安全処理を導入し、領域の形状バランスを調整可能にした。

### ■ BspVisualizer（デバッグ支援ツール）

- `Gizmos` を用いてツリーの深さ（階層）や領域分割の結果を画面上に色分け表示。アルゴリズムの挙動をリアルタイムでデバッグ・検証できる環境を構築した。

### ■ シングルトンパターン（MonoBehaviour Singleton）によるアクセス最適化

- 全体から参照されるマネージャークラスに対し、インスタンス自身を静的に保持するシングルトン構造を適用。
  * **背景**: はじめて使用した当時は静的・動的の理解が浅かったが、開発と学習を進める中で設計パターンとしての価値とアクセスの利便性を実感した。

### ■ データ駆動型設計（Data-Driven Architecture）

- マップを構成するデータや、生成で使用する部屋の形状を `ScriptableObject` やアセットとして保存し、そこから動的に読み込んで生成する仕組みを構築。
- `TileMap` からゲームの実行に必要な情報を得るため、タイルと設定情報を対応付けて保持・運用。

## 3. 技術的反省

### ■ 必要以上のファイル数の増加
クラスの疎結合化やデータ分離を試みた結果ファイル数が増加し、事前のフォルダ構造や依存関係の設計（UML）がない状態では管理が煩雑になる課題に直面した。

### ■ 基本情報技術者試験の学習と事前設計の重要性の実感
初期にデータ駆動型の使用を想定せずに開発を進めたため、新しい技法を途中から導入することに苦労した。その難しさから基本情報技術者で学んだUMLの必要性を実感した。

## 4. 今後の展望

- **静的地形データに基づく経路探索の事前計算**
  本システムで分離・生成した `TerrainMap` の静的なグリッド構造を活用し、敵ユニットなどの動的オブジェクトが利用する A* 経路探索のノード情報を事前に計算する処理を組み込む。
- **キャッシュ機構と両立する部屋データの動的変換（回転・反転）**
  `RoomDatabase` の遅延キャッシュ構造を拡張し、1つの `RoomData` プレハブから90度・180度回転および左右反転したデータを自動生成・保持する仕組みを構築する。
- **学術的探求とシステムの再構築**
  今回の開発で得た「設計とアルゴリズム」の反省と気づきをベースに、実装前にUMLによる厳密なアーキテクチャ設計を行い、今回の知見を活かしたより柔軟で拡張性の高いプロシージャル生成基盤の再構築に挑戦する。
